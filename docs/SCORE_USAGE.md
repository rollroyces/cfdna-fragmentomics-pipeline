# Using `cfdna-score` — Per-sample risk scoring

`cfdna-score` is the per-sample risk-score CLI for the cfdna-fragmentomics
pipeline. It scores a single cfDNA sample against the 627-sample
cross-study cohort trained in `honest_benchmark.py` (Section C) and
`multiclass_classification.py`.

> **⚠️  RESEARCH USE ONLY**
> The model was trained AND cross-validated on the same 627-sample cohort.
> Pooled OOF AUCs (~0.97 binary, ~0.97 macro) reflect the training-cohort
> performance; they do NOT generalise to independent cohorts. The CI on
> `p_cancer` estimates sampling variance of the pooled OOF score, not
> external-validation uncertainty. **Do not use this output to guide
> clinical decisions.**

---

## Quick start

```bash
# From a sample ID that already exists in labels_multiclass.tsv
cfdna-score --sample-id C311 --pretty

# Or via Python (no install needed)
python scripts/score_single_sample.py --sample-id HOT426 --out /tmp/hot426.json

# Save JSON to file
cfdna-score --sample-id C311 --out results/c311.json

# Skip bootstrap CI for faster runs
cfdna-score --sample-id C311 --no-bootstrap

# Smoke / test mode (1 seed × 2 folds, ~30 s)
cfdna-score --sample-id C311 --quick
```

### Risk-tier definitions

`risk_tier` is bucketed from `p_cancer` using thresholds derived from
the cohort's pooled OOF at standard clinical specificity points:

| `risk_tier` | Range                                  | Operating point           |
|-------------|----------------------------------------|---------------------------|
| `low`       | `p_cancer` < 0.6252                    | below spec=0.95 threshold |
| `medium`    | 0.6252 ≤ `p_cancer` < 0.9096           | between spec=0.95 and 0.98|
| `high`      | `p_cancer` ≥ 0.9096                    | at or above spec=0.98     |

The thresholds are calibrated from `results/sens_at_spec.json`
(generated by `scripts/sens_at_specificity.py`). They are operating
points, NOT clinical decision thresholds — see the disclaimer above.

### `p_cancer_class`

Multi-class OvR probabilities, **normalised to sum to 1.0** across the
5 kept classes (BRCA, HCC_J, HEALTHY, LUAD, PAAD). Classes with
n < 30 in the training cohort (CRC, OV, OTHER_C) are dropped; the CLI
loads them anyway as `NaN` so the JSON keys are stable.

The normalisation is monotone, so `argmax(p_cancer_class)` is preserved
vs. raw OvR.

## CLI flags

| Flag                       | Default                              | Notes                                              |
|----------------------------|--------------------------------------|----------------------------------------------------|
| `--sample-id S` (required) | —                                    | Sample in `labels_multiclass.tsv`                  |
| `--frag-tsv PATH`          | —                                    | FinaleDB frag.tsv.bgz file (alternative input)     |
| `--features-dir DIR`       | `data/features`                      | `{sample}.{delfi_*,fsd}.{npy,json}` cache          |
| `--labels PATH`            | `labels_multiclass.tsv`              | Sample → disease_class map                         |
| `--out PATH`               | stdout                               | Write JSON to file                                 |
| `--pretty`                 | off                                  | Indented JSON output                               |
| `--quiet`                  | off                                  | Suppress stderr logs                               |
| `--no-bootstrap`           | off                                  | Skip CI computation (faster)                       |
| `--quick`                  | off                                  | 1 seed × 2 folds OOF (smoke / tests; ~30s)         |
| `--cache PATH`             | `results/score_single_sample_oof.npz`| Cache OOF predictions across runs                  |
| `--no-cache`               | off                                  | Force re-fit of LR (slow)                          |

## Model details

- **Architecture**: Logistic regression, one-vs-rest, no PCA, `C=1000.0`,
  L2 regularised, `lbfgs` solver.
- **Features**: 5-channel DELFI (5 Mb ratio + 5 Mb coverage + 100 kb ratio
  + 100 kb counts + 196-bin fragment-size distribution) ≈ 63 246 features
  per sample, with per-study harmonisation (see `train_classifier._harmonize`).
- **Training cohort**: 627 samples (Cristiano 2019 + Jiang 2015 HCC).
  After the `n >= 30` class filter, 545 samples across 5 classes are
  used (BRCA, HCC_J, HEALTHY, LUAD, PAAD). The CLI keeps the dropped
  classes in the JSON keys for downstream stability.
- **Score provenance**: Each sample's `p_cancer` is its pooled 5-seed ×
  5-fold out-of-fold prediction — i.e., it was predicted by a model that
  never saw the sample during training. The full OOF matrix is cached in
  `results/score_single_sample_oof.npz` for fast repeated lookups.
- **Calibration**: No Platt / isotonic calibration is applied; the raw
  LR probabilities are returned. Risk-tier thresholds come from
  `roc_curve` operating points on the same pooled OOF.

## Streamlit / Gradio UI hint

The CLI output is plain JSON and trivially consumable by any web UI.
A real Streamlit app would be ~80 LOC (sidebar: file/path input, sample
picker, `--pretty` toggle; main panel: `st.json(out)` + a bar chart of
`p_cancer_class`). We deliberately defer that to a follow-up enhancement
to keep this CLI pure-Python, dependency-free, and CI-testable.

## Honest framing — "research use only"

This CLI is a *deployment-shaped demo* of the benchmark pipeline, not a
diagnostic product. The key caveats:

1. **No external validation.** Pooled OOF AUCs are computed on the same
   cohort that was used to train the model. The reported numbers are
   *internal validation only*.
2. **No clinical calibration.** Risk-tier thresholds come from
   `roc_curve` operating points, not from a calibrated clinical model.
3. **No tumour-informed priors.** Fragmentomics-only, as documented in
   the manuscript.
4. **Caveat about `--frag-tsv` mode.** The on-the-fly feature extractor
   is a *simplified* version of `extract_delfi.py` / `extract_fsd.py`.
   Use pre-extracted artefacts (`--sample-id` mode) for any real
   evaluation.

The CLI exists to make the benchmark pipeline *operationally usable* —
not to claim clinical readiness.
